# Personal FDE 的工作方法

本技能是面向个人知识工作的流程诊断实践，不是任何厂商官方发布的联合评分标准。v3 以观察、分工、试跑、复盘为主，不使用未验证的评分权重或厂商成效数字作为结论依据。

## 1. 观察真实工作，而不是只统计聊天

还原一项业务成果从输入到交付的步骤。逐项写出：当前输入、动作、产物、使用者做了什么、AI 已经做了什么、哪里发生返工。长会话可能含多个任务，不把它们机械压成一条流程。

借鉴 FDE 的现场观察思路：表面需求可能是对现有工作阻碍的表达。诊断要基于实际证据，不先假定用户不会用 AI。

## 2. 把建议做成一个可试用的流程

最低可用产物不是“建议使用 AI”，而是一份带输入、步骤、职责、检查和异常路径的 SOP。规则稳定且可检查的部分交给 AI；需要选择权和责任承担的部分保留给人。

先在一类任务上试跑，再扩展到其他类；不要把每个重复动作都建成一个新 Skill。能用已有模板、现有技能的收尾检查解决，就不另建系统。

## 3. 验证两件不同的事

- **实现验证**：脚本是否读取正确范围、报告是否可打开、引用是否存在、SOP 是否完整。可以当场测试。
- **业务成效验证**：使用者是否减少返工、输出是否真的通过验收、合作推进是否改善。必须等真实试跑或明确反馈，不能以渲染成功代替。

## 4. 形成有依据的反馈循环

扫描 → 证据化工作拆解 → 人机边界 → SOP 草案 → 用户确认后的试跑 → 同口径复盘。

历史记录区分旧版本参考、同口径增量、同数据复跑、建议采纳情况。没有采纳记录时标“未验证”，不推断成效。
