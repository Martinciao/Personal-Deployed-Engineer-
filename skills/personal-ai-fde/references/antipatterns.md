# 从症状到流程改造

以下是诊断线索，不是看到词语就命中的错误标签。先核对上下文，区分正常迭代、人的新判断和 AI 未遵守已给条件。

| 编号 | 观察线索 | 优先验证的原因 | 流程化建议 |
|---|---|---|---|
| A1 | 材料到齐后仍频繁补充基本事实 | 没有统一事实表或输入验收 | 先抽取事实、来源、版本、缺口，由人只确认关键项 |
| A2 | 先生成漂亮产物，再反复改内容方向 | 结构和业务目标未冻结 | 先确认信息结构，再排版；排版不改变业务口径 |
| A3 | 多次要求去模板化语气 | 风格规则未载入或未作为交付检查 | 复用已有写作规则，增加自检，不新建一套重复规则 |
| A4 | 同一材料不同文件编号反复混淆 | 缺少要求到证据的映射 | 用材料编号、国家/地区、适用对象、来源、状态进行逐项核对 |
| A5 | 一处事实修改后，其他产物未同步 | 多份文档手动维护 | 以统一事实表驱动多份产物，输出差异和检查清单 |
| A6 | 用户反复纠正“谁可以知道什么” | 业务意图与披露许可混在一起 | 人定义披露边界，AI 在已确认事实范围内起草并列风险 |
| A7 | 用户反复要求来源或纠正数字 | 研究与写作没有来源账本 | 先证据表、再判断；来源冲突显式列出，不自行补数 |
| A8 | 每次要周报都从零恢复进展 | 事件、待办、成果混用 | 先结构化进展记录，再汇报；状态升级由人确认 |
| A9 | 同一失败操作多次重复 | 工具/权限/接口条件未验证 | 先查阻塞，有限重试后停止；不绕过拒绝 |
| A10 | 长会话引用了旧版需求或文件 | 交付物和任务状态未明确 | 用阶段交接单标当前版本、已确认条件、待决点；按需要分会话 |
| A11 | 建了很多模板但仍重复起草 | 资产不可发现或没嵌入常用入口 | 明确复用哪个现成入口和需要补哪项检查 |
| A12 | 只因发生次数多就建议无人值守 | 没有确认输入稳定、异常路径、授权 | 人工触发试跑成功后再考虑自动触发 |

## 正向模式

有证据时明确保留有效做法：先确认模板再填内容；对外信息保留人工把关；具体指出对象、位置和期望；复用源文件而不是重复输入；明确说先讨论不要编辑。改造的目标是保留这些控制点，把机械处理交给 AI，不是删除所有人工环节。
